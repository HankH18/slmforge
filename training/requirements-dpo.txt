# The DPO trainer's environment -- .venv-dpo, NOT .venv.
#
# .venv is the GRADED environment (Python 3.11.15, transformers 5.15.1) and the
# repo's whole test suite and every gate depend on its exact package set. trl and
# peft are not installed there and must not be: a resolver that moved
# transformers to satisfy trl would break the graded environment. So the DPO run
# gets its own interpreter and its own resolution.
#
# Recreate it exactly:
#
#     /opt/homebrew/bin/python3.11 -m venv .venv-dpo
#     ./.venv-dpo/bin/pip install -r training/requirements-dpo.txt
#
# Created 2026-08-22 with Python 3.11.15 (/opt/homebrew/bin/python3.11) and
# pip 26.2.1 on macOS 25.4.0 arm64. Every version below is what actually
# resolved on that machine, recorded after the fact -- not a wish list.
#
# WHAT DID NOT HAPPEN, because it was the expected risk: trl 1.10.0 did NOT
# resolve transformers downward. .venv-dpo and .venv both hold transformers
# 5.15.1. The venvs are still separate, because that outcome is a fact about
# this resolution on this day, not a guarantee.
#
# NOT INSTALLED, deliberately: bitsandbytes. It ships CUDA kernels only, so
# neither configs/train.json's load_in_4bit nor its adamw_8bit optimizer can be
# reproduced on MPS. training/dpo_local.py says so in its docstring rather than
# substituting something and calling it the same recipe.
