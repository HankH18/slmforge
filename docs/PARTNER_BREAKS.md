# Partner breaks — before and after the adversarial retrain

The Adversarial Exchange assignment asks for one number and its counterpart:

> *"Your updated model must be re-tested against the prompts you received. Report
> how many still break it, before and after your retrain."*

This document carries that table. Every count in the generated block below is
**re-derived** by re-running `constraints.checkers.check` over the model outputs
stored in `runs/breaks/*.json` — no stored verdict is read — and
`scripts/replay_breaks.py --check docs/PARTNER_BREAKS.md` refuses the document
unless the block regenerates byte-identically. Editing a digit here fails the
check rather than changing the claim.

> **Status: BEFORE measured, AFTER pending.** The v4 corpus is being generated and
> no retrained checkpoint exists yet. The `after` column appears here when it does,
> produced by the same script against the same frozen exam.

## What was received

20 confirmed breaks from an exchange partner who attacked the published
checkpoint `c19712a7` and served it exactly as `docs/PIVOT_SPEC.md` §3 specifies —
merged fp16, single user turn, no system prompt, `enable_thinking=False`,
`do_sample=False` passed explicitly, 512 max new tokens. They scored against
**this repo's published ambiguity rulings**, not their own reading, and discarded
three of their own candidate breaks because of the doubles-only ruling for
`no_quotation_marks`.

All 20 reproduce under our checkers. Independent corroboration that they served
the model honestly: on a fresh run of the same pinned checkpoint, **6 of the 20
outputs came back byte-identical** to their recorded response and 14 differed —
which is what greedy decoding on identical weights does across their merged fp16
and this machine's MPS bfloat16.

## Where the breaks landed, and why that is the finding

Fourteen of the twenty are in families this project publishes as **holding**:

| family | published tuned violation rate | breaks |
|---|---:|---:|
| `no_quotation_marks` | 0.000 | 3 |
| `banned_phrases` | 0.000 | 1 |
| `no_lists` | 0.019 | 5 |
| `banned_words` | 0.056 | 5 |

Those rates are not wrong; they are **narrow**. All ten entries of
`datagen.task_pool.NUDGES` are permission-to-relax attacks — the family the
partner scored **0 for 4** against. The corpus drills the attack the model already
beats and contains no example of the two that work: **format compulsion** (demand
an output shape that cannot exist without the banned element) and **subject
compulsion** (make the banned token the topic). Direct instruction override
failed outright; the model is robust to being *told* to ignore a rule and fragile
when the requested artefact cannot exist without breaking one.

## How to reproduce this

```bash
# re-derive the table from the committed run JSONs (no model, no network, no spend)
python scripts/replay_breaks.py --check docs/PARTNER_BREAKS.md runs/breaks/before.json

# confirm the frozen exam has not drifted
python scripts/freeze_breaks.py --check

# re-measure BEFORE from scratch (pulls the pinned checkpoint; no judge, no API spend)
python scripts/replay_breaks.py \
    --model hf:HankH18/qwen3-1.7b-forbidden-constraint-holder@c19712a72932b503f28fe063d1962acc9e8c3fb8 \
    --out runs/breaks/before.json --label before
```

Predictions for the `after` column were committed **before** the v4 corpus existed:
see [`RETRAIN_PREREGISTRATION.md`](RETRAIN_PREREGISTRATION.md) §2, which fixes
numeric thresholds for the single-turn rows, the multi-turn rows and the held-out
type, so this table can fail on terms set in advance.
